# Copilot Premium — Prompt Library

**Resource:** GitHub Copilot Agent in VS Code. 300 premium requests/month = ~10/day.
**NOT a task queue.** A reference library of tight prompts for high-leverage scenarios you'll hit during your own coding sessions.

Copilot Agent in VS Code has access to: files, terminal, git, test runners. You pilot it by chat — it's pair-programming, not autonomous.

---

## When to burn a premium request (vs use inline autocomplete)

Premium request = best frontier model (Claude Sonnet / Opus / GPT-5). Use when:

- You need **architectural reasoning** (which pattern, which dep, which boundary)
- You need to **explain unfamiliar code** deeply
- You're **debugging something non-obvious** (stack trace doesn't tell the story)
- You want a **second opinion on a design** before committing
- You need to **draft a migration path** that's risky

Don't use for:
- Inline autocomplete (that's unlimited baseline)
- Formatting, renames, simple refactors (Codex or direct edit)
- Tests that follow a clear pattern (Claude /loop handles)
- Commit messages, README updates (inline fine)

## Prompt library

### P-01 — Review an AI-written commit

```
Review the diff in this commit (git show HEAD) as if you were a staff engineer who owns this repo. Focus:
1. Contract violations (types, API shapes, CLAUDE.md conventions)
2. Missing error handling at system boundaries
3. Tests that pass but don't test the real behavior
4. Scope creep beyond what the sprint task requested
5. Forbidden patterns (any, --no-verify, TODOs added)
Don't comment on style. Don't suggest unrelated refactors. Output: 3 bullets for top issues, 3 for strengths.
```

### P-02 — Debug non-obvious test failure

```
I have a failing test with this output: [paste test output + stack]
Context: this code was just generated by a /loop agent, I haven't read all of it.
Before suggesting fixes, explain in 3 sentences what the test is trying to verify, what's actually happening, and why they differ. Then suggest the minimal fix.
```

### P-03 — Decide between two implementation approaches

```
I'm implementing [feature] and have two approaches in mind:
Approach A: [description]
Approach B: [description]
Context: [codebase style, perf constraints, team size]
Constraints: [from CLAUDE.md / ADRs]
Walk me through tradeoffs in 200 words. Then recommend one. Explain what would make the other approach correct.
```

### P-04 — Architecture question during live session

```
Read [file or folder]. Explain the current architecture pattern in 5 sentences. Then answer: [specific question about extending it].
```

### P-05 — Risk assessment before a risky change

```
I'm about to change [file/function]. Proposed diff: [paste].
This code is used by [list callers]. 
Before I apply: what's the blast radius? What tests cover this path? What could silently break?
Output: impact summary + required test changes + 1 rollback scenario.
```

### P-06 — Coaching rule YAML review

```
I'm authoring a coaching rule for the library. Draft:
[paste YAML]
Read ADR-013 (coaching library format) before reviewing.
Check: threshold plausibility, FP risk, physics-correctness, explanation template quality at each skill level, drill linkage. 
Output: 3 specific improvements or "looks correct" with reasoning.
```

### P-07 — Telemetry/physics question

```
I need to detect [weakness type] from telemetry.
Channels available: [brake, throttle, steering, speed, g-lat, g-lon, yaw rate, rpm, gear].
Sample rate: [N Hz].
What signals best capture this weakness? Suggest a decision rule with thresholds that a rule-based engine could implement. Cite physics rationale.
```

### P-08 — Schema migration planning

```
I need to add/change [field/table] in [repo]. Current state: [paste schema].
Migrations policy (ADR-003): UUIDv7 IDs, Alembic async, RLS enforced.
Design the migration: DDL steps, data backfill (if needed), rollback SQL, app-code changes required, feature-flag gating.
```

### P-09 — Performance deep-dive

```
Profile output: [paste output or flame graph screenshot].
Code in question: [file + function].
Current: [metric] at [value]. Target: [metric] at [target].
Identify top 3 bottlenecks + suggested optimizations. Prioritize by impact / risk ratio.
```

### P-10 — PR review when loop review flags [SCOPE_FLAG]

```
A /loop agent committed with [SCOPE_FLAG] = [N] lines on a task that expected ~100-300.
Task description: [paste from sprint file]
Diff: [git show SHA]
Decide: is the scope blowup justified (necessary dependencies, correct-but-overreaching design), or genuine scope creep? Recommend: keep / split / revert.
```

### P-11 — Coaching article technical accuracy review

```
Article draft: [paste full article]
Check:
1. Every physics claim — is it accurate?
2. Every telemetry-signature claim — can it actually be detected in sample data?
3. Every drill — is it realistic?
4. Any safety-critical advice (real-world driving) — sound?
Flag inaccuracies with specific correction. Don't rewrite; tell me what to fix.
```

### P-12 — Stripe/billing integration concern

```
Scenario: [describe — e.g., user on 14-day trial upgrades on day 12, what happens to the 2 remaining days; or: webhook missed during deploy, how do we reconcile].
Read lap-backend/app/billing/ current implementation.
What's the current behavior? Is that correct? If not, what's the fix with minimal blast radius?
```

### P-13 — Security audit request

```
Review: [endpoint / file].
Check: authn (auth middleware applied), authz (RLS or per-user check), input validation (Pydantic), rate limit (if applicable), no secrets leaked in logs, CORS appropriate.
Output: list of findings (sev: low/med/high) + one-line fix for each.
```

### P-14 — CI/CD pipeline question

```
My GitHub Action [paste .yml or job name] is [failing / slow / flaky].
Log: [paste].
Diagnose root cause. Propose fix. If caching could speed up, show exact cache step.
```

### P-15 — Third-party library choice

```
I need a library for [purpose] in [TypeScript|Python|Kotlin|Swift].
Constraints: [license, size, maintenance activity, Node/browser/both].
Give me 3 options + tradeoffs + recommendation. Avoid libraries you're not sure are maintained in 2026.
```

## Daily burn rate

~10 premium/day × 30 days = 300. Roughly split:
- 2-3 per morning commit spot-check (P-01, P-02)
- 2-3 per afternoon architecture question during your own coding (P-03, P-04, P-07)
- 2-3 per risky-change assessment (P-05, P-08)
- 1-2 per day for specific scenarios (P-06 rule review, P-11 article review)

If you run out mid-month, the inline (non-premium) Copilot still works for continuation coding — you just lose frontier-model reasoning.

## Where to use Copilot vs Claude /loop vs Codex

| Scenario | Tool |
|---|---|
| Autonomous repo-wide work, scheduled | Claude /loop |
| Autonomous side-quest, manually fired | Codex |
| Your keyboard, needing smart completions | Copilot inline |
| Your keyboard, needing architectural reasoning | Copilot premium (use the library above) |
| Hands-off research / prose | ChatGPT |
| Design | Figma + Claude Design |
